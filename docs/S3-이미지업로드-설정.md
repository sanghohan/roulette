> 비용과 무관하게 실제로 뚫려 있던 구멍들이 함께 잡혔기 때문입니다 (9-1 참고).

탁구 게시판의 이미지/영상 파일을 AWS S3에 저장하도록 켜는 방법입니다.
인증 키를 코드/서버에 넣지 않고 **EC2 인스턴스 역할(IAM Role)** 로 안전하게 처리합니다.

---

## 1. S3 버킷 생성
1. AWS 콘솔 → S3 → **버킷 만들기**
2. 버킷 이름: 예) `donjiral-uploads` (전 세계 유일해야 함)
3. 리전: **EC2와 같은 리전**으로 (예: 아시아 태평양 시드니 `ap-southeast-2`)
4. **퍼블릭 액세스 차단 설정** → 이미지가 웹에 보여야 하므로 차단을 **해제**합니다.
   (4개 체크박스 해제 → 경고 확인) — 단, 아래 버킷 정책으로 `uploads/` 읽기만 공개합니다.
5. 생성

## 2. 버킷 정책 (uploads 폴더만 공개 읽기)
버킷 → **권한** → **버킷 정책** → 아래 붙여넣기 (버킷 이름 교체):
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadUploads",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::donjiral-uploads/uploads/*"
    }
  ]
}
```
→ `uploads/` 안의 파일만 누구나 **읽기** 가능. 업로드(쓰기)는 아래 IAM Role만 가능.

## 3. EC2에 IAM 역할(Role) 붙이기
서버가 키 없이 S3에 업로드하도록 권한을 부여합니다.
1. IAM → **역할** → **역할 만들기**
2. 신뢰 주체: **AWS 서비스 → EC2**
3. 권한: 아래 정책을 인라인으로 추가 (버킷 이름 교체)
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject"],
      "Resource": "arn:aws:s3:::donjiral-uploads/uploads/*"
    }
  ]
}
```
4. 역할 이름: 예) `pingpong-ec2-s3` → 생성
5. EC2 콘솔 → 인스턴스 선택 → **작업 → 보안 → IAM 역할 수정** → 방금 만든 역할 연결

## 4. 백엔드에 환경변수로 켜기
`docker run` 할 때 S3 관련 환경변수를 넘기면 됩니다. `run.sh`가 이미 환경변수를
전달하도록 돼 있으니, 실행 시 아래처럼 지정하세요(또는 run.sh에 기본값 추가):

```bash
docker rm -f pingpong-api 2>/dev/null || true
docker run -d --name pingpong-api --restart unless-stopped \
  -p 8080:8080 \
  -v "$HOME/pingpong-data:/app/data" \
  -e APP_CORS_ALLOWED_ORIGINS="https://www.donjiral.net,https://donjiral.net" \
  -e S3_ENABLED=true \
  -e S3_BUCKET=donjiral-uploads \
  -e S3_REGION=ap-southeast-2 \
  pingpong-api
```

확인:
```bash
curl -F "file=@/path/to/test.jpg" http://localhost:8080/api/uploads
# {"url":"https://donjiral-uploads.s3.ap-southeast-2.amazonaws.com/uploads/....jpg"}
```
그 URL을 브라우저에서 열어 이미지가 보이면 성공.

## 5. (선택) run.sh에 S3 기본값 넣기
매번 환경변수 치기 번거로우면 `backend/run.sh`의 docker run에 위 `-e S3_*` 줄을
추가해서 커밋해두면 됩니다. (버킷 이름은 비밀이 아니라 커밋해도 무방)

---

## 동작 방식
- 글쓰기 화면에서 파일 선택 → 프론트가 `POST /api/uploads`로 전송
- 백엔드가 S3에 저장하고 공개 URL을 돌려줌
- 그 URL이 글의 media로 저장되어 모두에게 보임
- S3를 안 켜도(`S3_ENABLED=false`) 글쓰기는 정상 동작하며, 파일 업로드만 막힙니다(링크 붙여넣기는 가능).

## 비용
- S3는 저장 용량/요청량 기반인데 이미지 위주 소규모면 월 몇 백 원 수준
- 프리 티어(가입 12개월): S3 5GB 저장 + 월 2만 GET/2천 PUT 무료

# 9. 비용 안전장치 (업로드를 다시 켜기 전 필수)

## 9-1. 애플리케이션 방어 (이미 코드에 반영됨)

| 방어선 | 위치 | 내용 |
|---|---|---|
| 관리자 인증 | `UploadController` | `/api/uploads` 는 `ADMIN_SECRET` 을 아는 사람만. 미설정 시 전원 차단 |
| 형식 검사 | `UploadController.sniff()` | 클라이언트가 보낸 Content-Type 대신 **파일 매직바이트**로 실제 형식 판별 |
| 건당 용량 | `app.upload.*` | 이미지 5MB / 영상 10MB |
| 일일 총량 | `UploadQuota` | 전체 하루 2GB 를 넘으면 429 |
| 횟수 제한 | `RateLimitFilter` | IP당 시간 20건·하루 50건, 전체 하루 2000건 |
| IP 위조 차단 | `RateLimitFilter.clientIp()` | 신뢰 프록시에서 온 요청만 XFF 참조, 맨 오른쪽 값 사용 |

> ⚠️ 이전 코드는 `X-Forwarded-For` 를 무조건 신뢰해서, 헤더만 매 요청 바꾸면
> **모든 속도 제한이 통째로 우회**됐습니다. 업로드뿐 아니라 `/api` 전체에
> 해당하던 문제라 이번에 함께 고쳤습니다.

## 9-2. AWS 쪽 방어 (콘솔에서 직접 설정)

### (1) 라이프사이클 규칙 — 가장 중요
버킷 → **관리** → **수명 주기 규칙 생성**

**규칙 A: 미완료 멀티파트 업로드 정리**
- 접두사: 없음(버킷 전체)
- ☑ 만료된 불완전 멀티파트 업로드 삭제 → **1일**

> 실패한 멀티파트 업로드 조각은 **콘솔 객체 목록에 보이지 않는데 과금은 됩니다.**
> 버킷이 비어 보이는데 요금이 나오는 전형적인 원인입니다. 반드시 켜세요.

**규칙 B: aicheck 임시본 자동 삭제**
- 접두사: `tmp/`
- ☑ 객체의 현재 버전 만료 → **1일**

**규칙 C: 구버전 정리 (버저닝을 켠 경우)**
- ☑ 객체의 이전 버전 영구 삭제 → **7일**

### (2) AWS Budgets 예산 알림
Billing → **Budgets** → 예산 생성 → 월 예산 **$5** (또는 원하는 금액)
- 실제 비용 80% / 100% 도달 시 `sanghohan@gmail.com` 으로 메일
- 비용 이상 감지(Cost Anomaly Detection)는 이미 켜져 있으나,
  **하루 3회까지만 재계산**되므로 예산 알림을 같이 두는 게 안전합니다

### (3) 퍼블릭 읽기의 전송량 비용도 기억할 것
현재 버킷 정책은 `uploads/*` 를 누구나 읽을 수 있게 열어둡니다.
저장 비용과 별개로 **데이터 전송 비용**(시드니 기준 약 $0.114/GB)이 발생하며,
같은 파일을 반복 다운로드하는 것만으로도 요금이 늘 수 있습니다.
트래픽이 늘면 CloudFront 를 앞에 두거나 버킷을 비공개로 돌리세요.

```bash
# 1. 실제 저장량 확인 — 정말 수십 PB 인가?
aws cloudwatch get-metric-statistics \
  --namespace AWS/S3 --metric-name BucketSizeBytes \
  --dimensions Name=BucketName,Value=s3-donjiral-uploads \
               Name=StorageType,Value=StandardStorage \
  --start-time 2026-07-01T00:00:00Z --end-time 2026-07-21T00:00:00Z \
  --period 86400 --statistics Average --region ap-southeast-2

# 2. 콘솔에 안 보이는 미완료 멀티파트 업로드 확인

  --bucket s3-donjiral-uploads --region ap-southeast-2

# 3. 계정의 모든 버킷 목록 (모르는 버킷이 있는지)
aws s3 ls

# 4. 누가 무엇을 올렸는지 (CloudTrail 이 켜져 있다면)
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=PutObject \
  --region ap-southeast-2 --max-results 50
```

## 9-4. 업로드를 다시 켜는 방법
위 9-2 설정을 마친 뒤:
```yaml
# backend/src/main/resources/application.yml
app:
  s3:
    enabled: true
```
그리고 `ADMIN_SECRET` 이 설정돼 있는지 확인하세요. 비어 있으면
게시판 업로드는 아무도 통과하지 못합니다(의도된 동작).
